## Race and missing-evidence contract

The worker's `KRUpdateWorkflowFence` serializes admission and reservations, but it currently has **no trusted `getOwnerSnapshot` provider or policy injected into production**. Consequently `reserve remains unavailable` and fail-closed; `lib/update-idle-policy.js` can only classify a supplied candidate (not grant permission). Do not wire a positive producer merely because the file above exists.

Before positive update leasing, validate read-only snapshots of every owner under storage and Chrome API failures; establish in-process in-flight counters for mutations that may outlive persisted status; prove no stale-generation or prior-profile owner can attest idle; and run worker restart / simultaneous start-versus-reserve adversarial tests. The 15-owner set and owner-specific checks must be exhaustive, not inferred from missing rows. NativeHost apply and Chrome-open atomic replacement remain separately gated by parent [KAR-67](https://github.com/SaschaP1980/KleinanzeigenRenewer/issues/67).
